# PocketAgent 使用指南

这是 GitHub 可直接阅读的 Markdown 版。需要完整图文排版时，下载 Release 里的
`PocketAgent-UserGuide.html`，用浏览器打开即可。

## 1. 安装

1. 下载 Release 里最新版的 `PocketAgent-<版本>.apk`。
2. 手机提示“未知来源”时，允许当前浏览器或文件管理器安装。
3. 打开 App，阅读并同意隐私政策和用户协议。

Android 8.0 及以上可用；不需要安装电脑端程序。

## 2. 配置模型

1. 首页右上角打开设置，进入“模型来源”。
2. 选择 DeepSeek、OpenAI/Codex、Claude，或添加任意兼容接口。
3. 填入自己的 API Key，保存。
4. 回到对话输入 `/test`，确认接口连通。

支持三类接口：

| 类型 | 路径 |
| --- | --- |
| DeepSeek / OpenAI 兼容 | `chat/completions` |
| Codex / OpenAI | `responses` |
| Claude | `messages` |

API Key 保存在手机的系统密钥库里，不会上传到 PocketAgent 的服务器。

保存后在“编辑来源”里还有几个和回答质量直接相关的参数：

- **最大输出 tokens**：Claude 必填，默认 8192。数值太小会把长分析、长表格截断。
- **输出详略（Responses）**：默认跟随服务端，和桌面行为一致；选“低”能省 token，
  但回答会明显变短。
- **最大工具轮数**：一次提问里最多跑多少轮“模型 → 工具 → 回灌”，默认 24。

思考档位（`/reasoning`）默认取这个模型能给的最高档，对齐桌面 `model_reasoning_effort = "max"`；
以前不设档位会落到服务端默认（这些模型常见是 low），同样的问题手机上会明显更浅。
自己选过（包括选“默认”）之后就不再被覆盖；某个来源不接受该档位时，会自动退回服务端默认重试一次。

网关上的 `deepseek-*` 模型会自动使用 Chat Completions 工具协议，与 Mac 的 DeepSeek
adapter 对齐：保留并回传 thinking 内容、为旧工具轮补齐结果，搜索和只读工具可并行执行。
这不会改变模型本身，但会让工具循环、上下文回放和长任务完成度更接近 Mac Codex。

## 3. 配置远程连接

先确定用哪种拓扑，再填表单。

### 3.1 三种拓扑

| 场景 | “主机”填什么 | “跳板机” |
| --- | --- | --- |
| 同一局域网直连 | 目标机内网 IP | 留空 |
| 经公网跳板机 | 目标机内网 IP | 公网跳板地址 |
| 反向隧道 | `127.0.0.1` | 公网跳板地址 |

### 3.2 表单字段

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名称 | 自己识别的名字 | 家里 Mac / 训练机 |
| 主机 | 目标机地址；反向隧道填 `127.0.0.1` | `192.168.1.10` |
| 端口 | SSH 端口；反向隧道填隧道端口 | `22` / `2222` |
| 用户名 | 目标机登录用户 | `alice` |
| 跳板机 | 公网跳板地址，不需要就留空 | `jump.example.com` |
| 跳板端口 | 跳板机 SSH 端口 | `22` |
| 跳板用户名 | 跳板机登录用户 | `jump-user` |
| 远端工作目录 | 命令执行目录 | `~` |
| 工作区目录 | 文件、导出、同步写入目录 | `~/pocketagent` |
| 私钥 | OpenSSH / PEM 私钥文件 | `id_ed25519` |

App 目前两跳共用同一把私钥。请把同一把公钥同时加入跳板机和目标机的
`~/.ssh/authorized_keys`，否则第二跳会报认证失败。

### 3.3 同一局域网直连

手机和目标机在同一 Wi-Fi 或 VPN：

1. 主机填目标机内网 IP，端口一般填 `22`，跳板机留空。
2. 导入私钥，保存并点“测试连接”。
3. 看到 `CONNECT_OK` 和主机名即成功。

先在电脑上验证：

```bash
ssh -i ~/.ssh/id_ed25519 alice@192.168.1.10
```

### 3.4 经公网跳板机

1. 主机填目标机内网 IP，例如 `10.0.0.12`。
2. 跳板机填公网地址、端口和跳板用户名。
3. 电脑上先验证两跳能通：

```bash
ssh -J jump-user@jump.example.com:22 alice@10.0.0.12
```

跳板机必须允许 TCP forwarding（`AllowTcpForwarding yes`）。如果报
`administratively prohibited`，说明跳板机禁止转发。

### 3.5 Mac / 家里电脑反向隧道

目标机没有公网 IP 时，让目标机主动连跳板机，把本机 22 映射到跳板机的
`127.0.0.1:2222`：

```bash
autossh -M 0 -N \
  -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -o ExitOnForwardFailure=yes \
  -i ~/.ssh/id_ed25519 \
  -R 2222:localhost:22 \
  jump-user@jump.example.com
```

手机表单这样填：

- 主机：`127.0.0.1`
- 端口：`2222`
- 用户名：Mac 的登录用户
- 跳板机：`jump.example.com`
- 跳板端口：`22`
- 跳板用户名：`jump-user`

`2222` 是跳板机上的端口，不是 Mac 的 SSH 端口。先在跳板机检查：

```bash
ss -ltn | grep 2222
```

被占用就换一个端口，同时修改 `-R` 和 App 里的“端口”。

macOS 开机自启可以把上面的命令放进 `~/Library/LaunchAgents/` 下的 LaunchAgent，
设置 `RunAtLoad` 和 `KeepAlive` 为 `true`；Linux 可用 systemd user service。

### 3.6 私钥

```bash
ssh-keygen -t ed25519 -C "pocketagent"
ssh-copy-id -i ~/.ssh/id_ed25519.pub alice@192.168.1.10
ssh-copy-id -i ~/.ssh/id_ed25519.pub jump-user@jump.example.com
chmod 600 ~/.ssh/id_ed25519
```

然后在 App 里“导入私钥”，选择 OpenSSH / PEM 私钥文件。保存后私钥进入
Android Keystore 加密存储，不进入系统备份。导入成功后删除手机下载目录里的
临时私钥，也不要把私钥发到聊天或仓库。

### 3.7 常见报错

| 现象 | 原因 / 处理 |
| --- | --- |
| “还没有私钥” | 先导入私钥并保存 |
| `Connection refused` | 端口没开或反向隧道没启动；检查 `ss -ltn` 和 `autossh` |
| `Exhausted available authentication methods` | 公钥没加到跳板机或目标机，或用户名填错 |
| `Connection timed out` | 地址不可达或防火墙没放行；先用 `nc -vz` 测端口 |
| `administratively prohibited` | 跳板机禁止 TCP forwarding |
| Host key verification failed | 服务器换过系统或指纹变了；确认后清除旧指纹 |
| 测试成功但命令失败 | 远端工作目录不存在或没权限；先改成 `~` |

## 4. 工作区

在对话输入 `/workspace` 选择工作区：

| 选择 | 文件位置 |
| --- | --- |
| 手机本地 | App 私有目录 `files/workspace` |
| 远端主机 | 那台机器的 `~/pocketagent`（可改） |

切到远端后，工作区代码、日志和导出文件写入远端目录。手机仍保留用于浏览和同步的
会话副本及附件缓存；执行模型和代码的主要资源来自所选远端。

`/workspace` 选择远端主机后，App 会实际检测该主机是否安装 Codex（Mac、Linux 均支持）。
检测到后，新的消息会直接交给那台机器的 `codex exec`：使用那台机器的
config、sandbox、skills/MCP 和 DeepSeek adapter；手机当前选择的模型 id 和思考档位会传给
远端，因此选 `deepseek-*` 时走远端配置的 DeepSeek harness，选 GPT/Codex 时走对应 Codex 通道。
手机只负责会话、展示和保存远端 session id。

远端 harness 的思考过程默认关闭，避免把大量 reasoning 文本经 SSH 传回手机。输入
`/thinking` 切换显示，或使用 `/thinking on`、`/thinking off`；该命令只在
`/workspace` 已启用远端主机时生效。关闭时远端会先过滤 reasoning 事件，实际减少手机流量。

未检测到 Codex 的主机使用手机 harness，调用远端文件与 shell 工具。远端安装 Codex 后，
重新选择该工作区即可检测；已有对话每次打开后首次发送也会重新检测，避免沿用旧结果。
设置中的「测试连接」同时检测 Codex，远程主机列表和工作区选择面板会显示检测结果。
网络超时、Node 损坏等会报检测失败并允许重试，不会被当作未安装而静默改用手机 harness。显式调用 `remote_codex` 工具仍需要人工审批。

每台远端机器需自行安装兼容的 Codex CLI，并配置可用的模型、API 凭证、工具及 DeepSeek 适配器
（如使用该适配方案）。配置和原生会话保存在该机器自己的 `~/.codex` 中，不能把其他电脑的
`localhost` 服务当作远端已有服务。需要无人登录时可用的适配器，应在该机器配置系统服务或
启用 linger 的 systemd 用户服务。手机不向远端复制 API Key。

建议先在远端终端执行 `codex --version`，再在一个测试目录执行
`codex exec --skip-git-repo-check "只回复 OK"` 确认模型配置可用。
App 自动查找 PATH、Homebrew、`~/.local/bin`、独立 npm、NVM、fnm、mise、Volta、asdf、bun
的常见安装位置。非常规安装可在「设置 → 远程主机 → 编辑 → Codex 可执行文件」填写
绝对路径或 `~/` 路径，留空自动识别；不需要改 App 代码或绑定特定主机名。
检测同时检查 `exec --json` 能力；版本不兼容、Node 损坏和路径错误会明确报错。
修改地址、跳板或可执行文件路径后会重新检测。
私钥有加密口令时，在同一页面填写「私钥口令」；私钥和口令分别加密保存在手机上，
不会写进主机配置 JSON。每台主机分别导入身份，不会自动借用其他主机的密钥。
如果只在交互式终端配置了环境变量，还需确保非交互 SSH 命令能使用同一份凭证；不要把密钥写进
项目代码或公开教程。完成后在 App「设置 → 远程主机 → 测试连接」检查，
再在对话用 `/workspace` 选择它。检测验证程序启动与 JSON 输出选项，不消耗模型 token，也不等同于 API 鉴权测试。
没有手机模型来源时，远端会使用其默认模型；手机已选择模型和档位时会传给远端，
因此所选模型也必须在远端可用。

远端整轮执行受那台机器自己的审批配置控制，手机不会逐条弹窗批准远端内部工具。
首次使用前请检查远端账号权限与 sandbox；手机不会自动扩大远端权限。

独立部署后，只要目标服务器和 SSH 跳板、API 出网正常，就不要求另一台 Mac 开机。
不同机器的文件和历史仍相互独立，需要在历史管理中选择目标主机同步；切换工作区不会自动搬迁全部历史。

### 4.1 手机 harness 与远端 Codex 的边界

| 能力 | 手机本地 harness | 远端原生 Codex harness（Mac / Linux） |
| --- | --- | --- |
| 系统提示 | 随 App 内置 Codex 风格与工作契约；读取工作区及父目录的 `AGENTS.md`，`AGENTS.override.md` 优先 | 使用远端的 config、模型和项目指令 |
| 工具 | `fs_*`、多文件 `apply_patch`、`shell_exec`、`exec_command` / `write_stdin`（后台会话）、`ssh_*`、网页、PDF、图片、`update_plan`、MCP 工具与资源（HTTP）、只读子 agent | 本机 shell、Git、编译环境、MCP（含 stdio）、可写 subagents、完整 skills |
| 运行隔离 | App 沙箱 + 分类审批；`shell_exec` 能读 App 可访问的绝对路径，审批是安全边界 | OS 级沙箱（Mac seatbelt / Linux 沙箱），可按配置放宽 |
| 子 agent | `delegate_task` 只读委托：每轮 4 次、并行 2 个、10 步、4 分钟；不能改文件 | `spawn_agent` 可写、可互相发消息、可嵌套 |
| 计划与进度 | `update_plan` 渲染成勾选卡片，工具调用按「步骤 N」编号 | 原生计划树与更细的补丁/diff 展示 |
| 审批 | App 内按工具类别确认 | 远端按 sandbox / approvals 配置 |
| 上下文 | 手机统计 token，回合前裁剪或 `/compact`；工具循环中段也会按完整工具轮自动折叠 | 原生 session 自带压缩与续接 |
| 图片 | 支持在本轮输入图片和 `view_image` | 由远端 Codex 的图像处理能力执行 |
| 回传 | 本地模型流式输出 | JSONL 事件实时回传进度；最终正文整轮结束落库；思考默认在远端过滤，不占手机流量 |

因此重型代码任务在 `/workspace` 选中已安装 Codex 的远端时，会使用该主机的 harness；手机 harness
负责随手问答、手机文件、网页查询和轻量工具循环。

远端 harness 工作时，进度气泡会持续更新当前阶段：连接 session、执行命令、调用 MCP、
修改文件、生成回答。命令正文和工具名会显示，命令输出不会整段回传；未开启
`/thinking` 时，reasoning JSON 直接在远端过滤，不经过手机流量。

输入栏默认单行：键盘右下角是“发送”，右侧蓝色圆形箭头也可以发送；长文本直接粘贴即可，
不会再出现旧版输入框底部裁字的问题。

手机本地需要跑长任务时，可以让 agent 用 `exec_command` 启动后台进程，再用
`write_stdin` 轮询增量输出、写 stdin 或终止；这和 Mac Codex 的后台命令方式一致。

单轮工具循环里如果一次读文件、跑命令或抓网页产生的结果接近窗口上限，App 会在
下一次模型请求前折叠较早的工具记录，保留当前任务、最近工具轮和确定性的工具台账。
折叠以「assistant tool_calls + 对应 tool 结果」为原子单位，不会发出缺结果的半截请求。

每条工具调用在对话里显示为 `步骤 N` 卡片，顺序与执行顺序一致，展开可以看参数和结果，
和桌面 Codex 的多步轨迹对应。

模型调用 `update_plan` 时，计划会单独渲染成一张卡片：`✓` 已完成、`▶` 进行中、`○` 待办，
长任务不用展开工具输出就能看到走到哪一步。

手机本地 shell 是 Android 自带的 toybox，没有 `rg`、`git`、`node`，也装不了软件；
找文本和找文件用 `fs_search` / `fs_glob`。`shell_exec` 的输出太长时，结果会保留头尾，
同时把完整内容写到工作区的 `.pocketagent/logs/` 下并给出路径，模型可以继续用
`fs_read` 加 `next_offset` 读，不需要重复执行同一条命令。需要 `git`、编译或跑测试时，
把 `/workspace` 切到远端机器。

`ssh_exec` 同理：stdout/stderr 被截断时，完整输出会存到远端 `/tmp/pocketagent-exec-*.log`，
结果里给出路径，接着用 `ssh_read` 分页读即可；远端日志按时间命名，需要清理时可以自己删。

模型还可以用 `view_image` 直接看工作区里的图片（截图、图表、界面草图），
和桌面 Codex 的 `view_image` 对齐；单张上限 1.4MB，图片只在本轮上下文里有效，
下一轮要再看需要让模型重新调用一次。

### 4.2 MCP 服务器（HTTP）

Mac 上的 Codex 可以直接挂 MCP；手机版现在也能挂，但只支持 **Streamable HTTP**。
stdio 类型要先在本地起 node / python 进程，手机上跑不了——这种请放到远端机器，
用 `/workspace` 选那台机器再 `remote_codex`。

配置步骤：

1. 设置 → 工具扩展 → MCP 服务器 → 右上角「添加」；
2. 填名称、地址（`https://…/mcp`），服务器需要鉴权时再填访问令牌；
3. 点「测试连接」确认能列出工具，再点「保存」。

要知道的几点：

- 令牌保存在本机 Keystore，不写进会话、日志或同步文件；界面上只显示「已保存」，不会回显。
- 保存后 App 会在后台拉一次 `tools/list`。工具名是 `mcp__<服务器>__<工具>`，
  `/mcp` 查看服务器和工具，`/mcp refresh` 强制刷新；停用某台服务器后它的工具立即消失。
- 服务器如果提供资源（`resources/list`），还会自动出现 `mcp__resources__list` 和
  `mcp__resources__read`：列出文档/数据条目并按 uri 读取。不支持资源的服务器会明确说明，
  不会静默返回空。
- MCP 工具默认**每次确认**，并且不提供「本次会话都允许」。嫌吵就在 `/permissions`
  里整类放行 MCP——那等同于信任你配置的这些服务器。
- 结果超过 3 万字符会保留头尾并提示省略；需要全文时让服务器返回链接，或把内容写到远端文件再读。
- MCP 返回的内容按外部数据处理，和网页一样不会覆盖系统规则；只配置你自己信任的服务器。

### 4.3 只读子 agent（`delegate_task`）

模型遇到“几个互不依赖的调研”时可以自己调用 `delegate_task`，派子 agent 分头去查，
主 agent 继续往下做。和 Mac 的 subagent 比，手机版刻意收窄了范围：

| 项 | 手机子 agent |
| --- | --- |
| 工具 | 只有只读的 `fs_read` / `fs_list` / `fs_glob` / `fs_search` / `pdf_read` / `view_image` / `ssh_read` / `ssh_ls` / `http_get` / `web_search` / `skill_read` |
| 能不能改东西 | 不能写文件、不能删、不能跑命令，也不能再开子 agent |
| 上限 | 每轮最多 4 次委托、同时最多 2 个、每个最多 10 步、4 分钟超时、结论最多 1.2 万字符 |
| 上下文 | 子 agent 的中间过程不进主对话，只回一段结论；结论仍要主 agent 自己核对 |

需要真正动手改代码时，主 agent 会自己做（走正常审批）；子 agent 只负责查清楚。

## 5. 上下文同步

打开“设置 → 历史上下文”，先在顶部的“同步目标”下拉框选择一台已经配置好的
远程主机；不会再默认 Mac。

同步脚本随 App 内置。第一次连接某台目标机时，App 会通过已经配置好的 SSH
自动把它写入 `~/.local/bin/pocketagent-export-context`，校验 SHA-256 后设置为可执行；
版本变化时自动原子更新。用户不需要在电脑上另外下载或安装适配程序。

同步只是读取会话文件、比较版本并按需原子写入，不调用大模型来“合并上下文”。

- 每组会话独立成一条对话，不混窗口。
- 每个同步目标单独保存基线、冲突和删除记录，切换目标不会串上下文。
- 两边都改过会标冲突，可选择保留手机、保留远端或两个都留。
- 删除会写删除记录，之后同步不会自动拉回。Mac 上的文件先移入回收站。
- 同步走 SSH，目标机需要先配好私钥。

### 5.1 手机 → 电脑 → 手机 来回切换

这里有两种工作方式，续接逻辑是一致的：

- 没有启用远端 Codex harness：手机发模型请求，远端只执行文件/命令工具。
- `/workspace` 选中 Mac 等远端 harness：整轮直接交给那台电脑上的 Codex，使用它的
  config、模型、DeepSeek adapter、sandbox、skills 和原生 session。

重点是 session id 始终跟着同一组对话走。远端已经聊过的会话同步到手机后，选中它再
`/workspace` 到那台电脑，App 会直接续接原生 session（支持时使用 `thread/resume`，旧版本使用 `codex exec resume`），不会重新开一组，
也不会把历史压成摘要后重讲。`/workspace` 面板会显示当前对话是否已经绑定远端会话。

推荐的来回切换顺序：

1. 电脑先聊了一段 → 手机“设置 → 历史上下文” → 选那台电脑 → 同步。
2. 手机上打开同步来的对话 → `/workspace` 选同一台电脑和目录 → 继续发消息。
   首轮会续接电脑原来的原生 session；在手机上产生的新一轮也会写回同一份 rollout。
3. 回到电脑后可直接 `codex resume <会话id>`，不需要再让手机发一遍摘要，也不会多出
   一条重复对话。
4. 如果手机用的是本机 harness，聊完先“同步”；App 会把整组会话落成同 id 的原生
   rollout，电脑上同样可直接 resume。
5. 回到手机再点一次同步。两边都在这期间改过 → 会显示“冲突”，自己选保留手机、
   保留远端或两个都留，不会悄悄覆盖。

手机新建的会话第一次切到远端 harness 时，App 会先把手机上已有的正文落成该机的原生
session，再 resume 同一个 id；空会话也会先建立 session 元数据。因此第一次使用也不会
出现“手机一组、电脑又一组”的重复历史。

原生 session 会绑定到具体远端主机，避免把 A 电脑的 session id 拿去 B 电脑误续接；
切换 `/workspace` 到另一台机器时会明确显示“绑定在另一台主机”。

同步后会生成只读副本 `~/.pocketagent/sync/from-phone/<会话id>.md`，方便在电脑上直接
查看手机内容；每次同步会刷新，手改副本会被覆盖。原生记录位于
`~/.codex/sessions/…/rollout-*-<会话id>.jsonl`。

如果只处理一组，不必点“同步全部”：在历史列表里点这一行的“同步此条”。
App 只读取这一条的远端版本，变化时才传输这一条的正文。

同步采用增量清单：上次同步后远端会话完全没变时，远端只返回一个清单令牌，
不传全部会话列表；本机没有改动就不会下载或上传任何正文。Mac 端会缓存会话索引，
只重新读取文件大小、修改时间或 inode 发生变化的会话，避免每次重扫整库。

要注意的几点：

- 在电脑上**新建**会话再同步回来，会是一条**新的**独立会话，不会并进原来那组。
- 手机上 `/compact` 压缩过的会话，同步时以手机为准，压缩掉的历史不会被灌回来。
- 电脑上的同一组还在生成回答时，手机拿到的是点击同步那一刻的快照；等电脑这一轮结束后
  再点一次“同步此条”，最后一条回复才会完整进入手机。
- 桌面 Codex 的内部审批历史、审批结果 JSON 和环境注入消息不会同步到手机，
  只同步真正的 user / assistant 对话正文，避免额外卡片和上下文污染。
- 默认同步所有历史（`POCKETAGENT_SYNC_LIST=0`）；按版本比较，只传输需要更新的组。
  元数据缓存位于 `~/.pocketagent/sync/context-index-v1.json`，权限为 `0600`，不保存正文。

### 5.2 恢复误删与永久删除

在“设置 → 历史上下文”选择对应的同步主机，点击“回收站：恢复 / 永久删除”。
列表读取的是所选主机上实际存在的回收站文件，每组会话独立显示标题、删除时间和文件大小，默认不勾选。

1. 手动勾选需要处理的历史；也可用“全选 / 取消全选”。
2. **恢复所选**：将选中的文件搬回原位置，只清除成功恢复的这些组的删除记录。
   然后点“同步全部”，把恢复的对话重新拉回手机。原位置已有文件时不会覆盖。
3. **永久删除所选**：先核对确认框中的数量和标题，再点“确认永久删除”。
   仅清理这些组在当前主机回收站里的文件，不能恢复；删除记录仍保留，后续同步不会自动拉回。
4. 未选中的历史保持原状。某些组失败会留在列表中显示原因，可重试；不会把整批误报为成功。

永久删除按批发送（每批最多 512 组），每批只扫描一次远端回收站，避免大量历史逐组往返 SSH。
网络中断后可重试，已经删除的组会按成功处理，不会因此清掉删除记录。

Mac 回收站位于 `~/.pocketagent/trash`，如果已在电脑上清空，则不能恢复。
远端脚本版本过旧时，App 会在下次连接时自动更新。永久删除只清理此功能管理的会话文件，
不删除用户另外保存的导出文件或备份。

另外还有一个轻量方案：会话里发 `/mirror on`，每轮结束把整段会话写到
`<工作区>/sessions/<会话id>.md`；在电脑上按 `## user` / `## assistant` 追加，
回手机发 `/mirror pull` 合并。它按正文去重、新内容追加在末尾，适合临时接力；
如果电脑改过而手机又写了一轮，App 会拒绝覆盖并提示先 pull。

### 复制消息和思考过程

用户消息、AI 回答、表格和代码都可以长按选择并复制。每条消息右下角有“复制整条消息”
按钮；AI 消息会按“思考过程 / 回答”分段复制。思考过程标题右侧还可以单独复制思考内容。
如果远端思考过程被 `/thinking` 隐藏，它不会出现在整条复制中。

### 工具权限 `/permissions`

输入 `/permissions` 会弹出七个类别的开关，改完立即生效并写入当前模型来源，
下次启动仍然保留：

| 类别 | 包含的工具 | 默认 |
| --- | --- | --- |
| 搜索与抓网页 | `web_search`、`http_get` | 放行 |
| 读文件与列目录 | `fs_read`、`fs_list`、`fs_glob`、`pdf_read`、`view_image`、`ssh_read`、`ssh_ls` | 放行 |
| 写文件 | `fs_write`、`fs_edit` | 每次确认 |
| 删除文件 | `fs_delete` | 每次确认 |
| 本机命令 | `shell_exec` | 每次确认 |
| 远端命令与写入 | `ssh_exec`、`ssh_write` | 每次确认 |
| MCP 工具 | `mcp__<服务器>__<工具>` | 每次确认 |

也可以不开面板，直接用命令行改：

```
/permissions web off      # 抓网页改回每次确认
/permissions write on     # 放行写文件
```

私钥、`.env`、云厂商凭据这类敏感路径即使放行了“读文件”也仍然会单独确认一次，
避免网页里的提示注入把密钥读走。写、删、执行命令放行后不再逐次询问，
请只在信任当前模型来源时打开。

## 7. 安全

- API Key 和 SSH 私钥保存在 Android Keystore，主密钥不可导出。
- 应用关闭系统备份；可选应用锁和防截屏。
- SSH 首次连接记住主机指纹，之后指纹变化会拒绝连接。
- 不要把私钥、API Key 或真实主机信息提交到 git、截图或聊天。
- 只用自己有权访问的机器和服务；共享 APK 前先确认接收方有权限。

## 8. 后台运行与保活

Android 会把切到后台的应用当成缓存进程冻结，代码和网络都会停住；荣耀、小米等
国产 ROM 还会在系统层再限制一层。PocketAgent 的处理是：

- 回复期间挂**前台服务**（通知栏可见）并持有 partial wake lock，锁屏也不休眠；
- 同步历史上下文时同样挂前台服务，切走不会停；
- 回复结束用 `stopService` 收尾，通知和唤醒锁不会残留。

建议再手动放行一次：

1. App 里：设置 → 后台运行 → **允许后台保持回复**，跳到系统的电池优化页面，
   把 PocketAgent 设为「不限制 / 允许后台活动」。
2. 荣耀/小米等：系统设置 → 应用启动管理 → PocketAgent → 允许自启动、手动管理。

对话页底部在未放行时会显示一行提示，点「去设置」可以直接跳转；放行后提示不再出现。

验证：发一条消息后立刻切到别的 App 或按电源键锁屏，30 秒后回来，回复应该是完整的
（带 `AI 生成 · in … · out …`），而不是中断或报错。

## 9. 常见问题

**为什么模型没有回复？**

先执行 `/test` 检查接口；确认 Key、地址和模型 id 正确。

**为什么远端连接超时？**

先在电脑上执行同样的 `ssh` 命令；电脑也连不上时，问题在跳板机、端口或私钥，
不在 App。

**切到别的 App 或锁屏后回复中断？**

App 在回复期间会挂前台服务和唤醒锁；如果仍然中断，多半是 ROM 限制了后台。
打开“设置 → 后台运行 → 允许后台保持回复”，把本应用加入电池优化白名单
（荣耀/小米等还需要在系统的“应用启动管理”里允许自启动）。

**回答只显示了一半？**

先看结尾有没有「回答被截断」的提示：网关用输出上限结束时，App 会自动接着写一次。
如果仍缺内容，多半是模型或中转站提前结束，可以把问题拆小，或直接说「继续」。
旧版本（0.1.22 之前）留下的半截消息属于历史数据，无法自动补全。

**远端会话在电脑上怎么继续？**

同步完成后，手机提示里会给出 `codex resume <会话id>`。在电脑上执行它就能接上
手机这组上下文；只读查看也可以打开 `~/.pocketagent/sync/from-phone/<会话id>.md`。

**换手机后 Key 还在吗？**

不在。Key 和私钥不跟随备份，需要重新填；会话可以从远端重新同步。

**能只保存在手机本地吗？**

可以。模型请求仍会发给你配置的服务商；工作区默认在手机 App 私有目录。

## 运行中补充要求与调整方向

Agent 正在思考、回复或执行时，仍可在输入框输入文字、添加附件并发送。
这适用于普通对话、`/goal` 自主任务，以及 `/workspace` 选择的远端 Codex 工作区。

- **等待读取**：已保存到本次运行的待处理队列，尚未被 harness 接受；上限 8 条。
- **已读取补充要求**：harness 已接入真实的用户消息，后续步骤会结合新要求执行；这不表示任务已经完成。
- 手机本地生成回答时，会结束当前生成请求并带着补充要求重新规划。已完成的工具结果保留，旧草稿放入折叠过程，不混入新的最终正文。
- 已开始的工具先结束；尚未开始的旧操作会跳过，再依据新要求决定是否执行。需要立即中止时请点**停止**。
- `/goal` 中可以直接补充限制，也可再次输入 `/goal 新目标` 调整目标；补充消息优先于自动续跑。
- 远端通过 Codex app-server 的 `turn/steer` 将消息送入当前原生会话，并续用远端完整上下文。远端不支持此协议时，会明确提示在本轮结束后发送。
- 远端是否接收若因断线等原因无法确认，会保留待处理内容并暂停自动重发；请先同步核对远端会话，再决定是否清空待处理内容，避免同一操作执行两遍。

清空待处理内容只会撤回尚未被接入的要求，已经送达的要求无法撤回；可以继续发送新要求说明修改方向。
补充要求按真实用户消息保存，不会把各个对话的上下文合并到一起。思考过程仍默认折叠。
